# MQTT Topic Naming Scheme

## Current setup
- Root: `workshop/sensors/`
- Structure: `workshop/sensors/{location}/{sensor_type}/{reading}`
- Examples: `workshop/sensors/bench-left/temp/celsius`, `workshop/sensors/cabinet-1/humidity/percent`
- 8 active sensors across three zones, each publishing every 30 seconds
- Broker on Raspberry Pi, retained messages enabled for critical readings

## Naming rules
- Lowercase only, hyphens for multi-word, no special chars except forward slash
- Never use spaces or dots in topic names
- Location codes: bench-left, bench-right, cabinet-1, cabinet-2, shelf-north, shelf-south
- Sensor types: temp, humidity, motion, light, pressure, voltage
- Units always in final segment: celsius, percent, lux, psi, volts

## Subscriptions and clients
- Home Assistant subscribes to `workshop/sensors/+/+/+` for dashboard
- Archive script listens to `workshop/sensors/#` with 100ms debounce
- Alerts trigger on `workshop/sensors/bench-left/temp/celsius` > 35
- Backup topic structure for failover: `backup/workshop/sensors/` (unused since July)
