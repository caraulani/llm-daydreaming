## Geo allowlist for calling app

Current blocklist approach too reactive. Need destination allowlist matrix to gate high-risk corridors before transaction.

## High-risk routes

- Nigeria/Ghana to US: $450+ calls, 15% chargeback rate. Flag >$300 first transaction.
- India/Philippines to AU: overseas remittance patterns, cumulative daily limits working better than per-call caps.
- Russia/Belarus: payment networks flagged after 24 Feb 2022. Holding at block.
- Pakistan/Bangladesh: inconsistent mobile verification. Require second factor for new destinations.

## Whitelist tiers

Tier 1 (auto-approve): UK, CA, AU, DE, FR, NL, US (domestic). Known merchant patterns, low chargeback.

Tier 2 (soft gate): Mexico, Brazil, Poland, Czech Republic. Require transaction metadata match: phone country code, card country, destination country consistency. 1-2 hour review window if flagged.

Tier 3 (hold for review): All others until pattern emerges. Average hold 4-6 hours. Last month: 340 Tier 3 transactions, 8 chargebacks.

## Implementation

- Load matrix into fraud rules engine by Nov. Blocks only if destination + caller origin combo in reject set.
- Test against Sept-Oct call logs: should catch 94% of chargebacks at <2% false positive rate.
- Merchant review cycle for Tier 2: currently manual, needs automation.
