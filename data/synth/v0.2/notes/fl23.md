# MQTT topic naming for sensor grid

## Current structure

- Root: `workshop/sensors/<location>/<device>/<metric>`
- Locations: bench, shelves, door, fume_hood, ambient
- Device IDs: temp01, humid02, air_quality_03, motion_04, power_monitor_05
- Metrics: value, status, battery, error, uptime

## Retained patterns

- Always lowercase, slashes for hierarchy, no spaces or special chars
- Retain device serial in metadata, not topic
- Publish interval in separate config file (MQTT_INTERVALS.yaml), not encoded in topic
- Retain historical topics for dropped sensors (marked readonly in broker config)

## Changes from v0.2 to current

- Split `workshop/data/<type>` into location-first hierarchy after fume hood relocation
- Added `status` subtopic for connectivity state (was inline before)
- Reduced redundant nesting: dropped old `sensor_` prefix on device IDs
- Battery voltage now separate subtopic, not concatenated with value
