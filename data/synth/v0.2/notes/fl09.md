Manual Review Queue Hold Durations

## Current State

Queue backs up to 40-50 cases on high-traffic days. Holds live open anywhere from 2 hours to 72 hours depending on complexity and staff availability. No hard SLA set yet, just informal "try to clear within 24 hours." High-risk blocks (velocity spikes, device blacklist hits) get priority.

## Pain Points

Customers call back multiple times on the same transaction, each escalating frustration. After 48 hours open, context degrades: IP geolocation changes, device state changes, associated account activity moves forward. Old holds become stale data fast. No automated state machine for transitions, so a case can sit "pending manual review" indefinitely if assigned reviewer is unavailable.

## What Matters

Hold duration has correlation with user churn. Cases held past 36 hours have higher re-dispute rates. Legitimate transactions (false positives) move to refund faster than fraud cases. Fraud cases need longer because manual review involves cross-checking linked accounts, call recordings, payment history.

## Rules to Try

Consider 24-hour auto-escalation to secondary reviewer, 48-hour escalation to supervisor. Don't auto-release; just notify. Track hold duration per case type in metadata. Separate queues for velocity vs. device vs. account reputation might help, but adds overhead splitting staff.
