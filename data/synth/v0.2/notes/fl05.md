Rubric wording changes reduced judge disagreement

## Initial rubric problems
- Original "factual accuracy" definition too vague, judges interpreted differently
- "Relevance" had 3+ valid readings across the team
- No threshold examples; each judge used different mental baseline
- Sept run showed 22% disagreement on 40-item sample

## Changes made
- Split "accuracy" into three: factual claims, numerical precision, date/source correctness
- Rewrote "relevance" with explicit scope: "directly addresses the user's stated question"
- Added 2-3 concrete examples per criterion (good/bad/borderline)
- Specified exact phrasing for borderline cases instead of "use judgment"

## October retest
- Same 40 items, fresh judges unfamiliar with Sept scoring
- Disagreement dropped to 8%
- Categories with examples showed tighter clustering than those with vague language
- "Numerical precision" criterion still had outliers, needs iteration

## Next
- Pilot the refined rubric on new LLM family (OpenRouter models)
- Document which example pairs were most clarifying
- Archive Sept version for audit trail
