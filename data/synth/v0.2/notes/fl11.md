# Incident Timeline: Payment Processor Report

## Detection and Initial Response

- Started noticing flagged disputes Sept 5, morning
- 43 fraudulent charges across 12 unique cards, all under $10 each
- Pattern: midnight to 4am UTC window, three consecutive days (Sept 3-5)
- Processor auto-flagged after breach threshold, around 11am Sept 5
- Disabled new card intake immediately, locked live environment

## Transaction Details

- Cards from six countries, no geographic clustering
- All routed through API endpoint for premium features unlock
- Tokens looked valid at auth time; no cvv mismatch flags
- Reverse lookups show 8 of 12 are business cards, issued within 30 days
- Amount consistent with lowest tier subscription test

## Log Review and Evidence

- Pulled auth logs, payment service logs, card handler events from Sept 1 onward
- Identified spike in token refresh calls on Sept 3, 14:22 UTC
- Session IDs suggest coordinated testing, not random automation
- No database breach or credential compromise detected in backend
- Logs packaged for processor compliance team by Sept 6, 2pm

## Processor Submission

- Timeline document drafting (due Sept 7)
- Card data isolation complete, ready for forensics handoff
- Prepared statement on remediation timeline, rate limits and token expiry tightening
