# Sampling the Hard Tail for LLM Evals

## The problem
Random sampling misses the 5-10% of cases where the model fails. Clients want to know whether their system can handle edge cases: ambiguous instructions, conflicting constraints, domain-specific jargon, hostile inputs. A 94% accuracy score with no visibility into failures is useless.

## Stratified pull
Split the corpus by expected difficulty tier before sampling. Flag cases manually by: instruction length (>400 words tends to break parsing), nested conditionals (if-then-then), rare entity types not seen in training, contradictions between user intent and constraints. Pull 30-50% from the hard tier instead of proportional.

## Adversarial markers
Look for inputs that triggered previous model errors. Reuse known failure modes from past runs: code generation with unusual syntax, translation of low-resource languages, multi-step reasoning with arithmetic. Don't retry blindly, but weight the pool toward those vectors.

## Track misses post-eval
After scoring, log which strata the model stumbled on. Next eval cycle, oversample that tier. Example: if spatial reasoning broke on 3 of 5 hard cases, bump spatial to 40% of next sample.

## Sample size vs coverage
50 items stratified beats 500 random for finding the ceiling. Clients usually need 20-30 hard cases to trust the assessment. Beyond that, marginal returns drop fast.
